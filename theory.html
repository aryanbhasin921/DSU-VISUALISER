Part 1 • The Motivation

The Problem Statement: Why Was DSU Needed?

Imagine you are running a huge social network like Instagram or LinkedIn with millions of users. Users are constantly forming connections:

🌐 The Dynamic Connectivity Challenge

You receive an endless stream of two types of queries in real time:
1. Connect(u, v): User u and User v just became friends.
2. IsConnected(u, v): Are User u and User v in the same mutual friend network?

Why Do Traditional Graph Algorithms Fail Here?

A computer science student's first instinct might be: "Why not just use BFS or DFS on a Graph?"

Standard Graph Traversal (BFS / DFS)

Why it's Too Slow

  • Checking if u reaches v requires walking the graph.
  • Each query takes O(V + E) time.
  • For $100,000$ queries on $100,000$ nodes, total time is $10^5 \times 10^5 = 10^{10}$ operations.
  • Result: Time Limit Exceeded (TLE)!
Component ID Array (comp[i])

Why it's Too Slow

  • Checking connection is fast: comp[u] == comp[v] takes O(1).
  • BUT merging requires looping over all $N$ elements to rewrite IDs: O(N) per merge.
  • $N$ unions take O(N²) overall.
  • Result: Still Too Slow!
💡 The DSU Solution

Disjoint Set Union (DSU) solves this exact problem by balancing both operations. It achieves both Union and Find in near O(1) amortized time, making dynamic connectivity virtually instantaneous!

Part 2 • Foundations

What is a Disjoint Set?

In mathematics, two sets are said to be disjoint if they have no elements in common — their intersection is completely empty:

Clan / Set A Leader: 0
0 1 2
Elements: { 0, 1, 2 }
Clan / Set B Leader: 3
3 4
Elements: { 3, 4 }
Clan / Set C Leader: 5
5
Elements: { 5 } (Singleton)
Disjoint Sets: No overlapping members (A ∩ B = ∅, B ∩ C = ∅, A ∩ C = ∅). Every element belongs to exactly ONE set!

DSU maintains a collection of such non-overlapping, partition sets over $N$ items.

The "Clan Leader" Intuition

Think of each set as an independent Clan. In every clan, there is exactly one recognized Leader (called the Root Representative):

  • When you want to know if two people belong to the same clan, you don't cross-check every member.
  • You simply ask: "Who is your clan leader?"
  • If person $A$'s leader is person $B$'s leader, they are guaranteed to be in the same clan!
  • When two clans decide to ally (Union), one clan leader bows down and designates the other leader as their new boss!
Part 3 • Under the Hood

Representing Trees with a Simple 1D Array

One of the most beautiful aspects of DSU is that we do not need pointers, nodes, or linked list classes. A forest of multiple trees is stored in a simple, flat integer array called parent[]:

Index (Node) 0 1 2 3 4 5
parent[i] 0 0 0 3 3 5
Interpretation Leader (0) Points to 0 Points to 0 Leader (3) Points to 3 Leader (5)
🔑 The Golden Rule of Representatives

A node i is the Root (Leader) of its component if and only if:
parent[i] === i

Forest representation in memory: 3 separate trees. Each node points upward to its parent. Roots (0, 3, 5) point to themselves!
Part 4 • Core Mechanics

The 3 Fundamental Operations

Every DSU data structure supports three basic operations:

1. makeSet(n)

Initializes $N$ elements. At the start, each element is isolated in its own independent set with size 1. Each node is its own representative.

makeSet(n) Initialization 
for (let i = 0; i < n; i++) {
    parent[i] = i;  // Everyone is their own leader: parent[0]=0, parent[1]=1...
    size[i] = 1;    // Each set starts with size = 1
}

2. find(x)

Finds the ultimate leader (root) of the set containing element x. We follow parent pointers upward until we reach a node where parent[root] == root.

3. union(x, y)

Merges the set containing x with the set containing y:

  1. Find root of x: rootX = find(x)
  2. Find root of y: rootY = find(y)
  3. If rootX === rootY, they are already in the same set — do nothing!
  4. If rootX !== rootY, attach one root under the other: parent[rootX] = rootY.
Part 5 • The Danger

The Flaw of Naive DSU: The Skewed Chain Trap

What happens if we implement union(x, y) naively by always attaching rootX to rootY without checking their sizes or heights?

Consider sequentially uniting: union(1, 0), union(2, 1), union(3, 2), union(4, 3), union(5, 4):

⚠️ Worst Case: Unbalanced Naive Chain Tree Depth: 5 Levels = O(N) Traversal!
Calling find(5) must traverse through 5 sequential pointers (5 → 4 → 3 → 2 → 1 → 0). On $N = 100,000$ elements, every query takes 100,000 steps — defeating the purpose of DSU!
⚠️ The O(N) Worst Case Trap

Without balancing heuristics, trees can degenerate into long linear chains (essentially linked lists). A single find(5) call must visit all $N$ nodes, reducing performance to O(N)! To prevent this, we introduce Union by Size or Union by Rank.

Part 6 • Balancing Heuristics

Optimization 1: Union by Size vs. Union by Rank

The golden rule to prevent degenerate chains is simple: Always attach the smaller tree under the root of the larger tree.

Option A: Union by Size (Recommended)

How it Works

  • Track element count in a size[] array (initialized to 1).
  • Compare: if (size[rootA] < size[rootB])
  • Attach rootA under rootB.
  • Update: size[rootB] += size[rootA].
  • Bonus: Gives you connected component sizes for free (crucial for coding interviews!).
Option B: Union by Rank

How it Works

  • Track upper-bound tree height in a rank[] array (initialized to 0).
  • Attach the lower-rank root under the higher-rank root.
  • Rank only increases by 1 when merging two trees of equal rank!
  • Strictly bounds tree depth.

Mathematical Proof: Why Tree Depth is Guaranteed O(log N)

Why does attaching smaller trees to larger trees guarantee height $O(\log N)$?

📐 The Doubling Principle

For a tree's height to increase by 1, it must be merged with another tree of at least equal size. Therefore, every time height increases by 1, the total number of nodes in that component must at least double!

A tree of height $h$ must contain at least $2^h$ nodes:
$$2^h \le N \implies h \le \log_2 N$$
Even for $1,000,000$ nodes, $\log_2(10^6) \approx 20$. Your tree will never exceed ~20 levels of depth!

Part 7 • The Ultimate Flattening

Optimization 2: Path Compression (The Game Changer)

While Union by Size reduces height to $O(\log N)$, Path Compression brings it all the way down to near O(1)!

Notice what happens when you run find(4) on a tree. You traverse:
4 → 3 → 2 → 1 → 0 (Root).

Key Insight: Since we already took the time to walk up to root 0, why should nodes 4, 3, and 2 keep their intermediate parent pointers? They all belong to root 0!

Before Find(4)

Tall 4-Level Chain

Requires traversing up 4 edges step-by-step.

⚡
Path Compression
After Find(4)

Flat 1-Level Star Tree

All nodes now point directly to root. Future finds run in O(1)!

The One-Liner Magic

In recursive code, path compression is implemented with just one single line:

Path Compression in 1 Line of Code 
function find(i) {
    if (parent[i] === i) return i;
    // Flatten the tree on the way back down the recursion:
    return parent[i] = find(parent[i]); 
}
🚀 What is O(α(N))? (The Inverse Ackermann Function)

When both Union by Size/Rank and Path Compression are combined, the amortized time complexity per operation becomes:

O(α(N))

$\alpha(N)$ is the Inverse Ackermann Function. It grows so unimaginably slowly that for any conceivable number in our universe:
For $N = 10^{600}$ (far more than the total atoms in the observable universe $\approx 10^{80}$), $\alpha(N) \le 4$!

In practical computing, DSU operations run in constant O(1) time!

Part 9 • Implementation

Production-Ready Code (All Languages)

Here is the complete, robust DSU implementation featuring both Union by Size and Path Compression: 

#include <vector>
#include <numeric>

class DSU {
private:
    std::vector<int> parent;
    std::vector<int> size;
    int numComponents;

public:
    DSU(int n) : parent(n), size(n, 1), numComponents(n) {
        std::iota(parent.begin(), parent.end(), 0); // parent[i] = i
    }

    int find(int i) {
        if (parent[i] == i) return i;
        // Path compression: flattens the tree dynamically
        return parent[i] = find(parent[i]);
    }

    bool unite(int i, int j) {
        int rootI = find(i);
        int rootJ = find(j);
        if (rootI == rootJ) return false; // Already connected

        // Union by size: attach smaller root under larger root
        if (size[rootI] < size[rootJ]) {
            parent[rootI] = rootJ;
            size[rootJ] += size[rootI];
        } else {
            parent[rootJ] = rootI;
            size[rootI] += size[rootJ];
        }
        numComponents--;
        return true;
    }

    bool connected(int i, int j) {
        return find(i) == find(j);
    }

    int getComponents() const { return numComponents; }
};
class DSU:
    def __init__(self, n: int):
        self.parent = list(range(n))  # Each node is its own parent
        self.size = [1] * n           # Each set starts with size 1
        self.num_components = n

    def find(self, i: int) -> int:
        if self.parent[i] == i:
            return i
        # Path compression
        self.parent[i] = self.find(self.parent[i])
        return self.parent[i]

    def unite(self, i: int, j: int) -> bool:
        root_i = self.find(i)
        root_j = self.find(j)
        if root_i == root_j:
            return False  # Cycle / already in same component

        # Union by size
        if self.size[root_i] < self.size[root_j]:
            self.parent[root_i] = root_j
            self.size[root_j] += self.size[root_i]
        else:
            self.parent[root_j] = root_i
            self.size[root_i] += self.size[root_j]
            
        self.num_components -= 1
        return True

    def connected(self, i: int, j: int) -> bool:
        return self.find(i) == self.find(j)
public class DSU {
    private int[] parent;
    private int[] size;
    private int numComponents;

    public DSU(int n) {
        parent = new int[n];
        size = new int[n];
        numComponents = n;
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            size[i] = 1;
        }
    }

    public int find(int i) {
        if (parent[i] == i) return i;
        // Path compression
        return parent[i] = find(parent[i]);
    }

    public boolean unite(int i, int j) {
        int rootI = find(i);
        int rootJ = find(j);
        if (rootI == rootJ) return false;

        if (size[rootI] < size[rootJ]) {
            parent[rootI] = rootJ;
            size[rootJ] += size[rootI];
        } else {
            parent[rootJ] = rootI;
            size[rootI] += size[rootJ];
        }
        numComponents--;
        return true;
    }

    public boolean connected(int i, int j) {
        return find(i) == find(j);
    }
}
class DSU {
    constructor(n) {
        this.parent = Array.from({ length: n }, (_, i) => i);
        this.size = new Array(n).fill(1);
        this.numComponents = n;
    }

    find(i) {
        if (this.parent[i] === i) return i;
        // Path compression
        return this.parent[i] = this.find(this.parent[i]);
    }

    unite(i, j) {
        const rootI = this.find(i);
        const rootJ = this.find(j);
        if (rootI === rootJ) return false;

        if (this.size[rootI] < this.size[rootJ]) {
            this.parent[rootI] = rootJ;
            this.size[rootJ] += this.size[rootI];
        } else {
            this.parent[rootJ] = rootI;
            this.size[rootI] += this.size[rootJ];
        }
        this.numComponents--;
        return true;
    }

    connected(i, j) {
        return this.find(i) === this.find(j);
    }
}
